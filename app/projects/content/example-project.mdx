## Adding a project

Drop a `.mdx` file in `app/projects/content/`. The filename becomes the slug, so
this file is served at `/projects/example-project`.

Frontmatter:

```mdx
---
title: 'Project name'
publishedAt: '2026-07-29'
summary: 'One sentence on what it does and why it matters.'
tech: 'Next.js, TypeScript, Postgres'
image: '/projects/screenshot.webp'
---
```

`tech` is a plain comma-separated string — it renders as the small chips under the
title, and it is also fed to the site's AI assistant so it can answer "what stack
does this use?".

`image` is optional. When set it renders at the top of the page, shows on hover in
the project list, and becomes the Open Graph image. Put the file in `public/` and
reference it with a leading slash. Without it, the site generates an OG image from
the title instead.

## Suggested structure

Write whatever you want, but this tends to read well:

- **What it is** — one paragraph, no jargon.
- **Why you built it** — the problem, honestly stated.
- **How it works** — the interesting technical decision, not a feature list.
- **What you'd do differently** — the part people actually remember.
